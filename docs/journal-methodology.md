# Journal Storage Methodology (Phase 6)

## 범위

Journal은 사용자가 생성한 통합 리딩과 직접 작성한 메모를 다시 볼 수 있게 한다. `/journal`은 날짜 내림차순 목록, 상세 리딩, 메모 수정을 제공한다.

초기 구현은 서버 데이터베이스가 아닌 현재 브라우저의 `localStorage`를 사용하는 교체 가능한 repository adapter다. 저장소 계약과 UI는 분리되어 있어 향후 서버 저장소로 교체할 수 있다.

## 저장 데이터

`JournalEntry` schema version 1은 다음 항목만 저장한다.

- 생성·수정 시각과 로컬 식별자
- 표시 이름
- 질문 카테고리와 질문 문장
- 오늘의 結 headline
- 타로 카드명·방향·자리
- 구조화된 `IntegratedReading`
- Palm 분석 실행 여부와 선택적인 구조화 `PalmResult`
- 사용자 메모

생년월일 원문, 카메라 `File`, Blob URL, object URL, data URL, 손바닥 원본 이미지는 저장하지 않는다. Palm 사진은 분석 단계의 임시 입력으로만 사용되고 Journal에는 구조화 결과가 우선된다.

## 결정성과 입력 제한

ID, 생성·수정 시각은 repository에 주입한다. 테스트에서는 고정 clock과 ID factory를 사용한다. 사용자 메모는 앞뒤 공백을 정리하고 최대 3,000자로 제한한다.

저장된 JSON을 읽을 때 schema version과 핵심 구조를 검증한다. 손상되거나 알 수 없는 레코드는 표시하지 않는다. 이는 계산 엔진이나 해석 결과를 다시 계산하는 과정이 아니다.

## 개인정보와 보존 한계

- 기록은 저장을 누른 현재 브라우저와 해당 브라우저 프로필에만 남는다.
- 다른 기기·브라우저와 동기화되지 않는다.
- 시크릿 모드 종료, 사이트 데이터 삭제, 브라우저 초기화 시 기록이 사라질 수 있다.
- 현재 단계에는 계정, 서버 백업, 내보내기, 삭제 복구가 없다.
- 민감한 정보는 메모에 적지 않는 것을 권장한다.

서버 동기화를 추가하려면 별도의 인증, 암호화, 보존 기간, 삭제 정책과 개인정보 동의 설계가 먼저 필요하다.
